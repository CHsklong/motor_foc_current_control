## 第十四轮（10:05）：g_boot_step=21 但 g_main_step≡1 —— 证明 main 不是"卡在代码里"，而是 CPU 整体停止推进

- **★ 结构性发现（本轮最有价值的一条，直接解释"S 曲线不转、其它三种正常"）**：
  - 电流/速度/位置（非 S）三种模式的给定都是**上电时一次性下发**（main.c:159-227 的 `hpm_mcl_loop_set_current_*/set_speed/set_position`），
    之后完全由 20kHz 中断闭环执行 —— **完全不需要主循环**。
  - 只有 S 曲线模式，运动命令 `scurve_move_delta()` 写在 `while(1)` 里（main.c:288）⇒ **必须靠主循环反复下发**。

- **代码层证明：main 不可能"卡"在 234→240 这段**（`g_main_step=1` 与 `=2` 之间）：
  - `g_heart_main++`：一条自增；
  - `dbg_probe_keep()`（dbg_probe.c:135-173）：一条**纯浮点加法链**，全是全局变量，**无函数调用、无指针解引用、无循环**；

  - ⇒ 该区间**在机器码层面没有可阻塞、可陷入的语句**。
- **全链路无死循环复核**（逐个读过）：

- **★ 唯一能让"一切都停"的机制（实锤代码路径）**：`debug/dbg_probe.c:16-24` 的 `exception_handler`：

  disable_global_irq(CSR_MSTATUS_MIE_MASK);   /* 冻结现场 */

  **这条正好解释"烧录程序之后过一会就过流"**（与"点 Debug 暂停"冻结占空比是同一种物理后果）。

- **"应急让路"的边界（关键）**：`ISR_RELIEF_ENABLE=1` 时每 4 拍只跳过
  `position_loop_pre()` + `hpm_mcl_loop()` + `position_loop_post()`（ctrl_foc.c:465-482）；
  **`scurve_isr_tick()`、编码器 SPI 读、ADC 取样、`isr_timed_end()`/窗口统计仍然每拍都跑**，压不下去。

  语义不变（1 圈 ≈ 1ms，`sc_dwell`=800 仍约 800ms），但 main 每圈**不再要求累积满 1ms 的 CPU 时间**。
  过 SES 命令行语法检查：error 0 / warning 0。

## 第十七轮（10:41）：根因定案 —— 整份固件按 -O0 编译
- **用户输入**：① J-Scope 截图（`g_enc_us_max`/`g_isr_us_win_max`/`g_loop_us_win_max`/`g_isr_win_over`）；
  ② **不开 J-Scope 重烧后电机仍不转** ⇒ 排除"调试器 halt 假象"，冻死是真实的。
- **截图读数（符号地址已用 nm 核对，读数有效）**：
  `g_enc_us_max` 117/117/117（恒）、`g_loop_us_win_max` 139/148/143.8、
  `g_isr_us_win_max` 221/239/231、**`g_isr_win_over` = 100（每一拍都超预算）**。
  ⇒ 20kHz 中断单拍 230µs，是 50µs 预算的 **4.6 倍**；CPU 100% 吃在中断里。
- **根因（三条独立证据）**：
  1. `readelf --debug-dump=info` 的 `DW_AT_producer`：编译命令行里**没有任何 `-O` 选项** ⇒ GCC 默认 **-O0**（ELF 构建于 10:41:10，与截图 10:41:44 同一份）；
  2. `bldc_foc.emProject` 的 Debug 配置 `gcc_optimization_level="None"`，产物在 `Output/Debug/`；
  3. 机制：`cmake/ide/segger.cmake:769-773` 用正则从编译选项里**提取** `-O*` 写成 `gcc_opt_level`；
     工程一个 `-O` 都没有 ⇒ 空串 ⇒ `get_gcc_opt_level()` 返回 `"None"`。**SDK 默认不设优化，是个静默陷阱。**
- **因果闭合**：中断超预算 4.6 倍 → CPU 全在中断 → main 零进度（heart_main=1 / boot_step=17 / main_step=1）
  → 只在 `while(1)` 的 S 曲线往复触发永不执行 → 电机不转。
  电流/速度/位置环不依赖 main（给定上电一次性下发、之后全在中断闭环）⇒「那三个正常」与「S 曲线不转」是同一条事实。
- **上一轮的错判已更正**：我曾用"小函数无栈帧 + gp 相对寻址"反推"代码是优化过的"，从而**否掉了 -O0 假设**——这个反推是错的
  （同 ELF 里链进 `__adddf3/__muldf3` 软双精度库函数，正是 -O0 的旁证）。判优化等级只认 DWARF producer 与 emProject 两处。
- **修复（2 处，已落地）**：
  1. `CMakeLists.txt` 加 `sdk_compile_options("-O2")`（SDK 自己的写法，见 `samples/lwip/mhd_wifi_demo`）—— 持久，CMake 重生成工程也保留；
  2. `bldc_foc.emProject` Debug 配置 `gcc_optimization_level="None"` → `"Level 2 balanced"` —— 不改 CMake 也能立刻重编生效。
- **量化（本轮实测）**：用 SES 工具链把 ISR 调用链上的文件分别按 -O0/-O2 编译比 `.text`：
  `hpm_mcl_loop` 8640→5976(1.45x)、`hpm_mcl_control` 7074→4398(1.61x)、`hpm_mcl_encoder` 3958→2682(1.48x)、
  `hpm_spi_drv` 3792→2312(1.64x)，合计 23716→15502 = **1.53x**（纯体积，运行期收益通常更大）。
- **-O2 安全前提已核**：探针全部 `volatile`（dbg_probe.h 82 处）；`g_sys_ms`/`g_encoder_isr_enable`/`adc_buff` 亦 volatile。
- **下一步**：Rebuild All + Download，重编后用 nm 核对地址，再看 `g_isr_us_win_max` / `g_isr_win_over`。
  若 `g_isr_win_over` 仍高 ⇒ 按成本排序：降 ISR 频率（20k→10k）→ 拆编码器段。
- **顺带记下（未改）**：`drv_spi.c` 的 `spi1_config()` 忽略 `spi_master_timing_init()` 返回值；
  该函数在分频不满足"整数、偶数、≤510"时返回 `status_invalid_argument` 且**不写 TIMING 寄存器**（`hpm_spi_drv.c:353-374`）。

## 第十七轮 —— -O2 修复**已验证生效**；S 曲线由"往复"改为"单向单次"

- **-O2 修复实证（10:57 抓拍，用户确认"修复了"）**：`g_isr_win_over` **100 → 0**、
  `g_isr_us_win_max` 231 → **31µs**（预算 50µs，占用 62%）、`g_enc_us_win_max` 117 → **8µs**、
  `g_loop_us_win_max` 144 → **22µs**。⇒ 中断不再吃满 CPU，main 正常推进。**"-O0 是根因"这条彻底闭环。**
  （同时说明 20kHz 不是必须降到 10kHz，-O2 后 31µs 留有将近一倍余量。）
- **本轮需求**：用户要把位置环测试从"反复运动（往复）"改成"走 S 型曲线"。
- **根源定位**：往复不是规划器或 ctrl_foc 的行为，就是 `main.c` 触发块里那两行 ——
  ① 走完把 `sc_dir = -sc_dir` 取反（+D 再 −D 回原点）；② 每轮无条件 `sc_dwell = SCURVE_DWELL_MS` 续期。
  `scurve_move_delta()` 语义是**相对当前规划位置 `s->p` 的位移**（`traj_s_curve.c:260`），所以取反即原路返回。
- **改动（2 处，语法检查 error 0 / warning 0）**：
  1. `app_cfg.h` 新增 `SCURVE_REPEAT_ENABLE`（**默认 0**）：1=往复（原行为），0=单向单次；
  2. `main.c` 触发块：加 `sc_armed` 闸门；单次模式下 `scurve_move_delta()` 成功后置 `sc_armed=0`，不再安排下一条；
     `sc_dwell` 初值改为 `SCURVE_DWELL_MS`（起始 800ms 等待窗口，留着把 J-Scope 采样跑起来）。
  **注意不能**用"`sc_dir = 0` 让它自己退出"的写法：`scurve_move_delta(0)` 会走 `D < SCURVE_MIN_DIST` 分支
  并 `move_cnt++`，导致 `g_sc_move_cnt` 每 800ms 空涨一次，破坏"只走了一次"的判据。
- **单次行程理论值（vmax=25 / amax=150 / jmax=4000，D=12π=37.70rad≈6 圈）**：
  形状①七段；`tj=37.5ms`、`ta=204.2ms`、`tv=1303.8ms`、**`t_all=1712ms`**；峰值 25 rad/s=238.7 rpm、峰值加速度 150 rad/s²。
- **DONE 之后的行为（已核）**：`ctrl_foc.c:74` 取 `g_pos_ref = g_sc.p`，修正器权限仅 ±`POS_CORR_MAX`=6 rad/s，
  叠加在速度前馈 `g_sc.v` 上 ⇒ 规划器 DONE 后 `v=0`、`p` 停在 `+POS_TARGET_DELTA`，位置环自然稳住终点。
- **判据**：`g_sc_move_cnt` 恒为 1、`g_sc_state` 最终停在 `DONE(2)`、`g_sc_dwell` 归 0 后不再回升。
- **仍未处理（提醒过两次，用户未表态）**：`POS_TARGET_DELTA` 的注释写"先收到 1 圈(2π)做安全首测"，实际值是 12π（6 圈）。
  单次模式下这个差别更直观：6 圈=1.71s，1 圈则 `t_all≈456ms`（`tv≈47ms`），更适合观察波形但行程短。
