## J-Scope/halt 采样过流 + 电机不转（15:25 确诊并修复）

### 现象
- 关 CAN、`step_response_p=1` 想跑位置 S 曲线，电机"不转"。
- 点 J-Scope 开始观测变量 → 电机抖动 → 电源过流保护跳闸。

### 过流根因：调试器 halt 冻结 FOC 环，但 PWM 不停
- J-Scope 变量采样是 **halt 模式**：J-Link 暂停 Cortex-M 内核读内存。
- halt 期间 20kHz FOC/电流环 ISR 停摆 → PWM 比较值不更新 → 电流环失调；
  但 HPM_PWM 默认 halt 时**不切安全态**，继续把"最后一拍占空比"当静态电压矢量加在电机上 → 定子过流。
- 每帧采样都 halt/恢复 → 一串不同扇区电流脉冲 → 机械抖动 → 最终过流跳闸。
- 修复：`drv_pwm.c` `pwm_init()`（PWMv1 分支，HPM5300 实际走这条）里加
  `MOTOR0_BLDCPWM->GCR |= PWM_GCR_DEBUGFAULT_SET(1);`
  → 内核被调试器 halt 时，PWM 输出经各通道已配的 `fault_mode=force_output_0` 进入安全态，不再施压。
  该位仅 halt 时生效，正常运行零影响。SES 语法检查 error 0/warning 0。
- 注意：DEBUGFAULT 是"halt 才生效"的保护；正常 halt 观测/断点现在安全，但**运行中断点+继续执行**也受保护。

### 电机"不转"的次因
- 配置本身正确：`FOC_POSITION_MODE=1`、`SCURVE_ENABLE=1`、`enable_speed_loop=true`，
  `scurve_plan(12.5π≈39.27rad)` 成功（shape 7，t_all≈1.78s），主循环 step_response_p 块会往复触发。
- 真正不转高度疑似 **keeper 把环锁死**：之前几次"点 J-Scope 过流"把 MCL 判了故障
  （`g_fault_src` 含 bit0 采样/过流=硬故障源，永不自愈）→ `g_keeper_blocked≠0`、PWM 关断。
- 验证手段（过流修复后 halt 观测已安全）：J-Scope 看 `g_keeper_blocked`/`g_fault_src`/`g_sc_move_cnt`。
  - `g_keeper_blocked≠0` → 真被锁死：先断电重启（g_fault_src 是 RAM 会清零，PWM 锁存由 KEEPER_FAULT_AUTO_CLR 清掉恢复），再确认；仍反复则临时 `RUN_KEEPER_ENABLE=0` 排雷。
  - `g_sc_move_cnt` 在涨 → S 曲线在动，电机该转；卡 0 → 检查烧录版本是否真带 step_response_p=1。

- 待办：重新编译烧录后，J-Scope 确认 g_can_err=0、CAN 盒出现 0x201(100ms)/0x202(500ms)；再发 0x100 验证回 0x1F0。

## 下午：关 CAN（CAN_CTRL_ENABLE=0）后上电行为随机（飞快/不转/抖动）—— 根因+修复

- 现象：CAN_CTRL_ENABLE=0 烧录后，上电有时飞快转、有时不转、有时抖动着转，行为随机。
- 根因：`main.c` 主循环里 `#if !CAN_CTRL_ENABLE` 块中 **step_response_s=1 仍会跑**（它是速度模式阶跃测试）：
  1. `board_delay_ms(2000)` 让主循环 2s 才转一圈 → `g_heart_main` 几乎不动；
  2. ctrl_foc.c 心跳监护（20ms 窗口）误判 main 被饿死 → keeper 被 ISR 以约 50Hz 代跑（清 PWM 故障/恢复输出/软重启环路随机高频发生），且 `s_relief=1` 应急让路常态化 → 每 4 拍跳 1 拍控制计算，电流环时序被破坏 → 抖动/异响；
  3. `user_speed.value` 每 2s 被抬 10 直到 50rad/s 且 enable=true；keeper 软重启环路时"不动已写入的给定" → 速度环吃到 50rad/s → **飞快（≈477rpm）**；
  4. 不转 = keeper 判故障后自愈锁死（g_keeper_blocked）或上电稳定期老问题。
- 修复：main.c 给 step_response_s 块加 `#if !FOC_POSITION_MODE` 编译保护（速度阶跃测试只属于速度模式）。语法检查 error 0 / warning 0。
- 教训：**关 CAN 时必须同时检查 app_cfg.h 的 step_response_s/p 是否适配当前模式**——这些自动测试块只在该模式的分支里有意义。
- 遗留：CAN 位置环抖动还没修。J-Scope 证据（13:45 截图）：速度反馈 motor0.encoder.result.speed 噪声极大（±大幅振荡），g_pos_ref/g_pos_abs 最终能对上（14.54/14.58）。初步分析：位置环 kp=10（SCURVE_POS_KP）按 τs³+s²+kp·s+Ki_eff 特征方程算阻尼比仅 ≈0.4（速度环闭环 τ≈24ms，Ki_eff=100），欠阻尼；外加修正器打满历史（POS_CORR_MAX=6 曾 ±6 打满）。待下一步：降 SCURVE_POS_KP 或降位置环带宽、复核速度反馈噪声来源。
