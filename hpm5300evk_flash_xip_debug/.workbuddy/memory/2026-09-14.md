# 2026-09-14 位置环调试

## 现象
跑位置环（FOC_POSITION_MODE=1，目标 1.5π 机械角）：有时正转到位，有时反转且一直转不停。

## 根因（三个叠加）
1. **位置环 kp 太小**：`BOARD_BLDC_SW_FOC_POSITION_LOOP_SPEED_KP = 0.05`。
   err=4.7 rad 时速度给定只有 0.245 rad/s（kp*err + ki*integral，积分被 integral_max=10 卡死只出 0.01）。
   0.245 rad/s 的速度给定 → 速度环 P 段只有 0.005 A，克服不了 0.004 N·m 静摩擦，
   全靠速度环积分攒 ~1 s 才动起来。仿真：4 s 只走 0.06~0.60 rad，肉眼看"一直在慢慢转"。
2. **方向随机**：每次上电对齐把转子吸到"电角度=0"的最近稳定点。p=4，
   电角度 0 对应 4 个机械位置、相隔 2π/4=90°，落在哪个取决于断电时转子停在哪。
   目标写成绝对角度 1.5π 时，err 符号每次都可能变 → 有时正转有时反转。
3. **位置反馈是单圈 [0,2π)，MCL 的 position_pid 不做 ±π 归一化**：
   `hpm_mcl_position_pid()` 直接 `err = setpoint - feedback`，反馈在 0/2π 回绕时 err 跳 ±2π，
   位置环输出翻符号 → 转过目标却以为还差一圈。

## 顺带发现的 MCL 坑
- `hpm_mcl_loop_init()`：`const_time.position_ts = &mcl_cfg->physical.time.speed_loop_ts`
  —— 位置环周期实际 = speed_loop_ts = 250us(4kHz)，工程配的 `position_loop_ts`(1ms) **根本没被引用**。
- `hpm_mcl_current_foc_loop()`：`MCL_FUNCTION_SET_IF_ELSE_TRUE(loop->ref_speed.enable, ref_speed,
  loop->ref_speed.value, loop->exec_ref.speed)` —— 只要 ref_speed.enable=true，
  位置环输出的 exec_ref.speed 每 250us 被 ref_speed.value 覆盖，位置环彻底失效。
  **位置环模式下必须 set_speed(enable=false)**。

## 本次改动（src/bldc_foc.c，编译 0 error）
- 新增 `encoder_abs_rebase()` + 重写 `encoder_get_abs_theta()`：把 MT6835 单圈角展开成
  连续多圈机械角（Δθ 归一到 ±π 后累加），消除回绕跳变。
- 新增 `POS_TARGET_DELTA (1.5π)`：目标改为"相对使能瞬间位置的增量"，方向唯一确定。
- 位置环参数重算：`kp 0.05→6.0`、`ki 0.001→0.0015`、`integral_max ±10→±20000`、
  `output_max ±50→±30`。
  依据：速度环 kp=0.02/ki=8e-5 → 主导时间常数 τ≈62ms；位置环 P+一阶滞后，
  ζ=1 时 kp=1/(4τ)=4.0，取 6 → ζ≈0.82、ωn≈9.8 rad/s(1.56Hz)。
  integral_max 必须 ≥ output_max/ki，否则积分补不出摩擦所需速度。
- main：位置环分支里显式 `user_speed.enable=false` + 清位置环积分 + `encoder_abs_rebase()`。
- 新增 J-Scope 探针：`g_pos_abs` / `g_pos_ref` / `g_pos_err` / `g_ref_speed`。

## 仿真结果
- 旧参数：4 s 位移 +0.138 / -0.055 / +0.603 rad，速度范围仅 ±0.1~0.22 rad/s。
- 新参数：0.79 s 到位，残余误差 <0.002 rad，峰值速度 32 rad/s，无反向、无超调。

## 待验证
烧录后 J-Scope 看 g_pos_err 应单调收敛到 0，g_ref_speed 峰值 ~30 rad/s 后回 0。
若仍有超调，把 kp 从 6 降到 4（ζ=1）；若响应太慢（>1.5s），提到 8~10。

# 分层后回归：速度环摆动/不转、位置环顿一下不转（同日下午）

## 现象
分层重构后：开环正常转、电流环正常；速度环来回摆动或不转；位置环顿一下然后不转。

## 根因（这个是决定性的）
**`boards/hpm5300evk/board.h` 307-312 行已经定义了整套 `BOARD_BLDC_SW_FOC_*_KP/KI`，
`hw_map.h` 先 include 它，导致 `motor_params.h` 里的 `#ifndef` 守卫整块被跳过，
board.h 的旧值一直在实际生效。** 也就是说此前所有改参数的动作都没生效：
- 速度环实际是 0.0074/0.0001（ωn≈59rad/s、ζ≈0.55，太软有超调），不是我以为的 0.02/0.00008；
- 位置环实际是 154.7/0.113/integral_max=10/output_max=50。
- 诊断线索：编译器报错 "did you mean BOARD_BLDC_SW_FOC_POSITION_KI"，
  说明该宏已定义（来自 board.h），而同块新加的宏未定义。

## 顺带查明的第二个坑
位置环用 `hpm_mcl_position_pid()`，与速度环 `hpm_mcl_control_pi()` **实现不同**：
- 速度环：`integral += ki*err`，`out = kp*err + integral`

我 09-14 那次按速度环语义整定（kp=6/ki=0.0015）是错的；已按真实语义重算。

  验证方式：`gcc -E -P` 展开后确认 0.02/0.00008、20/0.025、1200/30 全部生效。
- 位置环参数：kp 154.7→**20**，ki 0.113→**0.025**，integral_max 10→**1200**，output_max 50→**30**。
  （ωn=10rad/s、ζ=1：kp=2ζωn，ki=ωn²·Ts=100×2.5e-4=0.025；Ts=250us 因位置环实际 4kHz）
- 新增 `motor_set_loop_mode()`（motor.c/h）+ `MOTOR_RUN_LOOP_MODE`（app_cfg.h）：
  按运行模式设置 enable_speed_loop/enable_position_loop，速度环模式显式关掉位置环。
- `app_cfg.h`：三个模式宏加 `#error` 互斥检查（此前若 POSITION 和 SPEED 同时为 1，
  main 的 if/else if 会让位置环优先，速度给定根本不生效）。
- `USE_VIRTUAL_ANGLE` 从 app_cfg.h 移到 `sens_encoder.h`，断掉 sensor→app 的反向依赖。
- 新增 J-Scope 探针：`g_pos_integral`、`g_loop_status`、`g_enc_status`、`g_ana_status`、`g_pwm_enabled`；
  `drv_pwm` 新增 `pwm_output_is_enabled()`，用于区分"控制环没出力"和"被故障保护关断"。

## 位置环"正转→反转→正转 + 停下后摆动"（第 4 轮，同一天）
现象：速度环正常后，位置环运行时先正转、再反转、再正转停下，停稳后还小幅摆动。

根因（三个叠加，都在位置环 PI 上）：
1. **积分饱和（主因）**。MCL 的 `hpm_mcl_position_pid()` 是
   `integral += err`（不含 ki）→ 限幅 → `val = kp*err + ki*integral` → 限幅，**无抗饱和**。
   目标 12.5π=39.27rad 时 err≈39，integral 每 250us 加 39，7.6ms 就顶到 integral_max=1200，
   此后输出恒为 30rad/s，直到临近目标才开始退饱和（要 0.3s），必然冲过目标 → 反转 → 再拉回。
2. **固定输出限幅**。30rad/s 一路冲到目标附近才开始减速，而速度反馈有 5ms 滤波滞后，
   减速指令晚了 5ms 就是多走 0.15rad。
3. **到位后积分残留**。减速段结束时 integral≈130（折合 3.3rad/s），P 项只有零点几，
   一旦 err 越过死区边界，积分主导输出把电机推走 → 39.23~39.30 之间持续极限环。

修复（`control/ctrl_foc.c` 新增 `position_loop_pre/post()`，包在 `hpm_mcl_loop()` 外）：
- 接近限速：每拍改 `cfg.output_max = sqrt(2*150*(|err|-0.01))`，迫使提前减速
- clamping 抗饱和：输出撞限幅且 err 同向 → `integral = 本拍前的值`
- 平滑死区 + 积分泄放：死区内限幅 0、integral 按 2.0/拍 泄放到 0（约 16ms）
- `motor_params.h`：integral_max 1200→300（积分最多贡献 7.5rad/s，不再单独顶满输出）；
  新增 POS_DECEL_MAX=150、POS_ARRIVE_DEADBAND=0.01、POS_INTEGRAL_LEAK=2.0
- 新增探针 `g_pos_vlim`（本拍动态限幅），可在 J-Scope 直接看限速是否生效

仿真结果：反转峰值 -5.73→-0.06rad/s，到位 1.81→1.43s，残差 -2.15°→-0.41°，末端由振荡变静止。
ninja 全量构建通过（FLASH 104912B）。

调试要点：只用"限幅 + integral_max"压不住这类问题，必须让限幅随误差收敛（接近限速），
并且到位后把积分泄掉而不是冻结。

## 「为什么积分饱和 = 正转→反转→正转」机理复盘（第 5 轮，同天，用户提问）
新建仿真脚本 `tools/sim_pos_windup.py`（位置环4k + 速度环PI4k + 机械 J/Kt/粘性+库仑摩擦，
模型 A=固定限幅无抗饱和，模型 B=接近限速+clamping+泄放），复现并量化：

- A 的分段（目标 90°）：正转 0→114.5°(0-249ms) → 反转到 86°(249-971ms) → 正转到 96°
  **完美复现用户的"正转→反转→正转"**；B 只有正转到 94.3° 再微回 89.6°。
- 关键量化：err 在 93ms/90.11° 翻负，但输出 w_ref 到 121ms/110.02° 才翻负，
  **滞后 28ms、多冲 19.9°**；输出翻负后实际转向到 249ms/114.5° 才翻负，
  **再滞后 128ms（速度环软+机械惯性）、又多冲 4.5°**。合计过冲 24.6°。
- 手算判据（可直接用来估过冲）：积分饱和时积分项 = ki*Imax = 0.025*300 = 7.5 rad/s；
  要 kp*err 压过它需 err < -ki*Imax/kp = **-0.375 rad = -21.5°**。
  即"越过目标后还得再冲 21.5°，控制器才想起往回转"——这就是过冲下限。
- integral 59ms 顶到 300，退到 0 用了 227ms（这段电机一直在正转）。
- B 的 integral 峰值只有 77（远未饱和），终值 0，158ms 稳定。

结论：三段式方向变化的本质是**积分存量使输出符号翻转滞后于误差符号翻转**，
每次过冲都被"下一次过冲"纠正；反向饱和后剧情镜像重演，直到幅值衰减进摩擦死区才停。
调参可直接改脚本顶部常量复现。
